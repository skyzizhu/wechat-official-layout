# 方案：文排账号体系 + 文章云端保存 + 微信公众号草稿箱一键发布

> 状态：待评审 · 前置调研已完成（2026-10）
> 结论先行：**可行**。文排从「纯前端零后端」升级为「纯前端 + 极轻后端」：用户登录**文排自己的账号**，文章保存到**文排后台**（每篇独立、多端续写）；登录后可配置自己的公众号信息，一键推送草稿箱。

---

## 一、需求确认

1. **自有账号体系**：用户在文排网站注册/登录（不是第三方平台账号登录我们的站）
2. **云端文章库**：每份文章独立保存在文排后台——标题、内容、主题配置，可随时取回继续编辑（多设备续写）
3. **公众号直连**：登录用户可在「发布设置」里配置自己的公众号 AppID/AppSecret，一键把当前文章推送到**自己公众号的草稿箱**（用户去后台预览/群发，我们不代发）

> 澄清：知乎平台本身无创作 API（官方仅开放读取类接口），本案与知乎无关，不做知乎发布。

---

## 二、调研结论

### 1. 微信公众号草稿箱：✅ 官方支持，三个硬约束决定必须加后端

官方接口成熟：`draft/add`（新增草稿）、`material/add_material`（图片素材，草稿封面 `thumb_media_id` 必填）、`freepublish/submit`（发布，本期不做）。

| # | 约束 | 说明 |
|---|------|------|
| 1 | **CORS** | `api.weixin.qq.com` 不返回跨域头，浏览器直调必被拦截 → 必须后端代理 |
| 2 | **IP 白名单** | 获取 `access_token` 的出口 IP 必须加入公众号后台白名单（否则 40164）→ 必须有固定出口 IP 的服务端 |
| 3 | **AppSecret 安全** | 放前端等于交出公众号（含群发权限）→ 只能服务端加密存储、永不下发 |

### 2. 登录方式：微信扫码不可用，用自有账号

微信开放平台「网站应用」需企业资质认证（300 元/年，个人无法申请）。自有账号的现实选项：

| 方案 | 优点 | 缺点 |
|------|------|------|
| **邮箱魔法链接/验证码**（推荐） | 无第三方资质依赖，国内可达，免费邮件额度够用 | 需接邮件服务 |
| 账号密码 + 邀请码 | 零外部依赖，适合内测期 | 密码管理责任在自己 |
| GitHub / Google OAuth | 个人友好 | 国内访问不稳，公众号作者群体不合适 |

## 三、目标架构

```
浏览器（wol.yourtools.xyz，现有前端架构不动）
   │  同源 /api/*（fetch + 会话 Cookie）
   ▼
极轻后端（Cloudflare Workers / 云函数，固定出口 IP）
   ├─ /api/auth/*        注册 / 登录 / 会话（邮箱魔法链接或账密+邀请码）
   ├─ /api/articles/*    文章云存 CRUD（列表 / 读取 / 保存 / 删除 / 重命名）
   ├─ /api/images/*      文章配图对象存储（按内容 hash 去重）
   └─ /api/wechat/*      微信代理：AppSecret 加密保管（永不下发）
                         access_token 缓存（7200s）+ 素材上传 + draft/add 转发
   ▼
数据层（D1 / Supabase Postgres + 对象存储 R2/OSS）
   └─ users / articles / article_images / wechat_credentials
```

**本地优先原则（不破坏零上传心智）**：
- 不登录 = 与现状完全一致，全功能本地可用
- 登录后本地草稿仍是第一副本，云存是自动备份 + 多端同步；隐私说明同步更新

---

## 四、数据模型与同步策略

```
users             id, email, password_hash|magic_token, created_at
articles          id, user_id, title, markdown(排版用源码), theme_id,
                  font_size, accent_color, word_count,
                  created_at, updated_at(本地), synced_at(云端)
article_images    id, user_id, hash(内容摘要), data, width, height
wechat_credentials user_id, app_id, app_secret(AES-GCM 加密), verified_at
```

- **同步策略**：登录后自动双向同步；冲突以 `updated_at` 新者胜，被覆盖方保留为「冲突副本」防丢稿
- **图片**：按内容 hash 去重上传对象存储；文章内保存引用令牌（与现有本地图片库机制同构，云端只是多了远端一份）
- **文章列表后台**：标题、摘要、字数、更新时间；支持重命名 / 删除 / 搜索；删除进回收站 30 天

---

## 五、关键流程（微信草稿箱）

1. 「发布设置」填 AppID + AppSecret → 后端即时调 `token` 接口校验（同时验证 IP 白名单与接口权限），失败给开通指引
2. 点「推送到公众号草稿箱」→ 前端复用现有序列化器产出微信 HTML
3. 后端：取缓存 token → 正文图片逐张传素材库 → 封面缩略图（选用文中图或用户指定）→ 组装 `draft/add` → 推送
4. 返回草稿 ID +「去公众号后台预览/群发」直达链接；**不代用户群发**

## 六、分期计划

| 阶段 | 内容 | 依赖 |
|------|------|------|
| P1 | **本地多草稿管理**（列表/命名/切换/删除） | 无，立即开工；统一数据模型，是云端的地基 |
| P2 | 账号体系 + 文章云同步 + 后台文章列表 | 后端载体与登录方式拍板 |
| P3 | 微信发布设置 + 草稿箱一键推送 | P2（凭据要挂在账号下）|
| P4（可选） | 邀请码内测 → 开放注册；freepublish 自动发布灰度 | P3 |

## 七、风险与对策

| 风险 | 对策 |
|------|------|
| 用户公众号无草稿箱 API 权限（个人主体未认证订阅号可能受限） | 配置时实时校验并给开通指引；文档写明「需认证公众号」 |
| IP 白名单随部署变动失效 | 后端固定出口 IP；换平台提示重配 |
| AppSecret 泄露（事故级） | AES-GCM 加密落库、主密钥仅存环境变量、永不下发、一键清除重置 |
| 云存文章的隐私顾虑 | opt-in + 本地优先 + 隐私说明更新；未来可加端侧加密 |
| 账号安全（撞库/丢号） | 邮箱验证 + 登录限速；找回流程走邮箱；支持全量导出（JSON/MD 打包） |
| 后端成本 | Workers/云函数 + D1/R2 免费档可覆盖早期；邮件免费额度 |

## 八、决策点（需要拍板）

1. 登录方式：邮箱魔法链接（推荐）还是账密 + 邀请码？
2. 后端载体：Cloudflare Workers（推荐，出口 IP 稳定）还是自有服务器？

4. P1 本地多草稿是否先行启动（不依赖以上任何决策）？
